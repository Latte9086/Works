# 月の家計簿（ローカルWeb試作）

Olive利用通知を読み取り、利用月ごとに合計する試作です。iPhone向けのレスポンシブ画面ですが、ネイティブiOSアプリではありません。実データはIndexedDBに保存し、独自の外部サーバーには送信しません。サンプルとGmailの記録は分離しています。

## 起動

画面は「ホーム」「履歴」「設定」の3ページです（試作 v0.4）。ホームには月間合計・月の選択・Gmail接続または新着取得・最終取得日時だけを中心に表示します。下部メニューから履歴・要確認・除外済み、または接続設定・試用・データ管理を開けます。ページ移動は画面の再読み込みを伴わないため、Gmail接続は移動中も維持されます。ブラウザの戻る操作にも対応します。アプリ全体を再読み込みした場合は従来どおり再接続が必要です。

Node.jsがインストールされたPCで、このディレクトリから実行します。追加ライブラリのインストールは不要です。

```powershell
npm start
```

ブラウザで http://localhost:4173 を開いてください。別ポートの場合は `node server.mjs 4174` のように指定します。終了はターミナルでCtrl+C。

「サンプルを取り込む」で2026年11月の利用成功2件・利用不可1件を読み込みます。合計は1,786円です。もう一度押しても増えません。月を変えるとその月の支出を表示します。サンプルは提供PDFから必要項目を抜粋・再構成し、氏名やメールアドレス等を含めていません。実メール本文そのものの自動テストではありません。

「メール本文を貼り付ける」で実際の通知テキストも試せます。同じ内容の再貼り付けはSHA-256で照合します。Gmailからの同じメールはメールIDで照合します。貼り付けとGmailの記録は混ざりません。

## CSV取り込み（v0.5）

設定 → CSV取り込み → ファイルを選ぶ → 取り込み内容を確認 → 取り込む。三井住友カードのVpassクレジット明細CSV（今回提供された7列、名義・マスク済みカード・カード種別の先頭行）に対応しています。UTF-8/Shift-JISを自動判定し、引用符・カンマ入り店舗名にも対応します。銀行口座・デビットCSVは未対応で、異なる形式や壊れた行はファイル全体の取り込みを中止します。

請求月やファイル名ではなく利用日の月に、利用金額列（日本円）を計上します。海外利用もCSVの日本円額を用い、為替レートから再計算しません。Suica等へのチャージは支出。名義行・合計行は支出に含めません。返金・調整・分割・リボ等は要確認に残します。提供された202609.csvは8月利用25件・91,647円で、末尾の合計と一致することを確認しました。

同じ明細行は内容と同一行の出現回数からSHA-256のIDを作り、再選択しても追加しません。同一内容の利用が複数行ある場合は件数を保持します。氏名・カード番号・元CSV・レート備考そのものは保存しません。解析済み取引と照合用ハッシュを端末のIndexedDBに保存します。

Gmail接続済みなら同じアカウントの利用記録に追加します。未接続なら端末のCSV記録に保存し、初回Gmail接続時に同じ利用者の記録としてまとめます。別の人のCSVは同じブラウザに取り込まないでください。既存の同日・同額、または同日・同じ利用先の記録がある新規CSV行は、自動加算せず要確認に回します。CSVより後に届いたメールにも同じ重複候補チェックを行います。一致候補は同一取引の確定ではなく、為替や名称の違いで候補を検出できない場合もあります。重複は「ほかの記録で解決済み」、別取引なら「別の支出として計上」で確認できます。

## Gmail接続手順

### 取得エラー対策（試作 v0.3.1）

APIリクエストは少なくとも850ms間隔とし、403のuserRateLimitExceeded/rateLimitExceededや429等の一時エラーは休止して最大3回再試行します。403の権限不足・API未有効化・日次上限等は別の原因として詳細を表示します。

2026年11月5日、旧版で403表示を確認した後、v0.3.1で実際のGmailに再接続し197件の取得・保存完了を確認しました。旧版はエラー詳細を表示しなかったため、当時の403のreasonは未確定です。

通知は10件ずつ保存し、途中で通信が止まっても取得済みの保存可能な分を確定します。再取得では要確認を含め同じパーサーバージョンのメール本文は取り直しません。新しいメールを取得するたび、保存済みの要確認との照合は引き続き行います。画面に戻るたびの再取得を抑え、エラー後はボタン操作で再開します。初回や更新直後の再解析には数分かかることがあります。

1. Google Cloudでプロジェクトを作成し、Gmail APIを有効にします。
2. Google Auth PlatformでOAuth同意画面を設定します。個人試用では外部・テストモードとし、自分のGoogleアカウントをテストユーザーに追加します。
3. データアクセスに `https://www.googleapis.com/auth/gmail.readonly` を設定します。メールの検索・本文読み取りに使用します。Gmail全体を読み取れる権限であり、対象メールだけに制限された権限ではありません。
4. OAuthクライアントIDを「ウェブアプリケーション」で作成し、承認済みJavaScript生成元に、現在開いているアプリの生成元を登録します。今回のプレビューは **`http://localhost:4174`** です。通常の `npm start` で4173番を使う場合は `http://localhost:4173` も追加します。両方登録してかまいません。127.0.0.1や別ポートは別の生成元です。「承認済みのリダイレクトURI」ではなく「承認済みのJavaScript生成元」に登録してください。末尾の `/` やページのパスは付けません。
5. アプリの右上の設定でクライアントIDと取得開始日を保存します。クライアントシークレットは不要です。入力しないでください。
6. 「Gmailを接続」を押し、ご自身でGoogleログイン・読み取り許可を行います。

### エラー400: origin_mismatch

Googleに登録されたJavaScript生成元と、アプリを開いた生成元が一致していません。Google CloudのGoogle Auth Platform → クライアント → アプリに設定したIDと同じWebクライアントを開き、「承認済みのJavaScript生成元」に `http://localhost:4174` を追加して保存してください。設定反映に時間がかかる場合があります。反映後、エラー画面を閉じてアプリを再読み込みし、もう一度接続します。

このWeb試作はGoogle Identity Servicesのトークン方式です。アクセストークンはメモリだけに保持し、再起動・再読み込み・期限切れ後はユーザー操作による再接続が必要です。「起動するだけで毎回自動取得」は未完成です。同一セッションで画面に戻った際は、有効なトークンがあれば自動取得します。通常利用のiPhoneアプリ化ではネイティブOAuthと更新トークンのKeychain保存等を別途設計する必要があります。

Gmailの検索結果は全ページ取得し、処理済みIDのメール本文は取得しません。未対応形式は要確認とし、次回も解析を試みます。保存に失敗した場合は支出と処理済みIDが同時にロールバックします。処理済みにするためにGmail側の既読・ラベル・メール内容を変更することはありません。

公開先は https://kakeibo-latte.pages.dev/ です。Googleの許可元と指定された2名のテストユーザーは登録済みです。ローカルでのGmail取得は確認済みですが、公開先のGmail実接続は未確認です。テストモードの認証期限・Google側の権限審査等の制約に従います。

## 集計の範囲

### 解決済み通知の除外（試作 v0.3）

取得時に、新しい通知と保存済み記録をまとめて照合します。口座・支払いモード・利用日・利用先と取引番号または承認番号が一致し、対応先を一意に特定できるときだけ、元の要確認通知を「除外済み」へ移します。外貨通知の対応先には計上済みの日本円記録が必要です。日付・店舗・金額の類似だけでは解決しません。円の明細自身も既存の支出との重複を確認するまで要確認に残します。

番号がなく自動照合できない場合は、要確認の「ほかの記録で解決済み」で、すでに反映されている利用履歴を選んで確認できます。除外理由と対応先IDを保存し、再取得しても確認結果を維持します。これは通知の整理のみで、支出の追加・減額は行いません。返金は減額まで反映されているか確認が必要です。除外済みの「要確認に戻す」で取り消せます。対応先の記録が消えたときも要確認に戻します。

支払い金額・一定金額到達の通知は、個別の支出ではないため直接除外します。国内外の利用不可とは理由を分けて表示します。負数の利用通知は返金・調整として要確認に残します。

更新後に再読み込みしてGmailへ接続すると、検索開始日以降の旧バージョンで処理したメールも一度再解析します。データ削除は不要です。画面最下部の「試作 v0.3」で更新を確認できます。

- `3,280円` と `3,280.00 JPY` はどちらも3,280円として計上します。JPYの小数部が0以外の場合は丸めず要確認とします。
- KRWなど外貨額しかない通知は「円換算待ち」にし、合計に含めません。独自レートで換算しません。日本円額が届いた後の自動照合・元記録の更新は未実装なので、変更通知は引き続き要確認です。
- 過去の「金額を確認できません」は次回のGmail取得で再解析します。既存の計上済み記録や保存領域の削除は不要です。

- クレジットとデビットの通常利用通知を利用日（日本時間）で計上します。チャージも通常利用通知として届けば計上されます。
- 利用不可は除外し、IDと理由を保存します。金額が書かれていても加算・減算しません。
- 件名・送信元・取引部分を確認します。未知の変更・返金通知は要確認に分け、加算しません。メールの真正性を送信元表示だけで保証するものではありません。
- 別メールIDの通知は上記の照合条件でのみ解決します。承認番号だけでは一意とみなさず、同日同額だけでも除外しません。
- 通知対象外の継続課金、ATM出金、銀行口座振替等は網羅しません。銀行明細取り込み・資金移動の照合は未実装です。
- 取消・返金・金額変更の自動補正は未実装です。通知の合計は確定請求額や支出全体を保証しません。
- 要確認・除外済みは利用月が不明な場合があるため、月フィルターにかかわらず全件表示します。

## 保存とiPhone

ブラウザ・生成元ごとにデータが別になります。サイトデータ削除等で記録は消えるため、設定からJSONを書き出せます。JSON再取り込みは未実装です。本文とトークンは保存しませんが、利用先・金額・日時・承認番号・アカウント識別用メールアドレスは端末内に保存します。

PCのlocalhostはiPhoneからはアクセスできません。iPhoneで実際にGmail接続するにはHTTPSの配信先とそのOAuth生成元設定、またはネイティブアプリ化が必要です。現段階では外部公開していません。
